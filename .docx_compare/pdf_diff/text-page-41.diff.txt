+8.2 Future work
+A controlled usability test is the number one priority. When using the EasyRTG workflow, the 
+time to complete the task, number of configuration errors, and the need for assistance and a 
+validated usability scale should be compared to a baseline documented code. This no-code 
+claim would need to be verified in the course of this study, and it does not appear this can be 
+taken for granted from the architecture.
+Also, a policy should only be sensitive to changes in instructions – not a fixed goal – otherwise, 
+observe and velocity commands should be introduced at the same time within a single 
+episode. Then a campaign worker could propose and run tests/ audits of changes to the 
+rewards (but would still have to have a user-approval process as described in 4.4.).
+Other items to consider for future research include including terrain and sensor observations, 
+enhancing automatic dynamics checks, testing additional robots with similar seeds and 
+algorithm budgets, and quantifying the throughput on other GPUs. Instead of just exploring by 
+individual experiments, hyperparameters should be explored from a reproducible optimisation 
+perspective, e.g., Optuna [27]. Lastly, it is required to have domain randomisation (and 
+hardware export) before EasyRTG can boast of having a complete simulation to real robot 
+behaviour path. This stage is provided with a model relevant to DrEureka [18].
